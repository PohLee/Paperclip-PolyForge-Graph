# P0 approval recovery completion — 2026-11-19

Human gate and rework-limit resolutions require `expectedDecisionId` from the pending wait (`escalationDecisionId` or `decisionId`, respectively) and `expectedRunDigest` computed from the run snapshot shown to the owner. Core checks both inside its existing CAS transition before consuming the wait. The decision ID identifies the particular wait, including when a node waits again after rework; the run digest fences changes to candidate versions or other state during a wait. A committed request with the same idempotency key and identical semantic arguments returns its original result; reusing that key with changed arguments fails. For these two approval operations, the original digest is part of the idempotency fingerprint: an exact replay returns the receipt, while a missing or changed digest is rejected.

The native decision card includes the run digest in its version and sends both preconditions. The Graph UI receives the run digest from the worker and sends the displayed pending decision ID; the worker forwards both. The Pack host facade preserves the caller's digest instead of silently replacing it with a fresher one. Type declarations and existing in-repository callers were updated. External callers of these two Core methods and worker operations must supply both fields; unbound legacy requests now fail closed. Existing persisted waits already contain the decision IDs and need no migration.

Focused verification: `node --test tests/core/engine.test.mjs tests/core/evidence-contracts.test.mjs tests/e2e/native-decision.test.mjs tests/e2e/pack-host-support.test.mjs`. Coverage includes repeated gate and rework-limit waits, missing and stale IDs, concurrent distinct callbacks, exact replay and changed-request rejection, and monotonic reset counts. Native tests verify the handoff passes both preconditions and that a run change while a card is being resolved rejects its answer. Run digest changes can require issuing a fresh card even when a change is unrelated to the choice; this is intentionally conservative.

This change does not establish host dependency or merge/deploy finalization authority; those require trusted external facts and their own integration.
