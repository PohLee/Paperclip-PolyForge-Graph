# Contract verification and receipts

The `adlc-contract-verify` job runs every minute. It checks each enabled G2, G3, or G4 publication against the current Decision Record and its frozen manifest revision. For an open PR it checks the proposal branch and compares the expected contract with the prospective merge into current main. It posts the status for that gate on the PR head. When multiple active occurrences share a head and context, any failure makes that context fail. The job withdraws stale success when admission is revoked or a run is held. See [enablement and optional required checks](contract-merge.md) for the flags, contexts, and GitHub App permissions.

After GitHub reports a human or automatic merge, the job proves that main contains the reported merge commit. It checks the exact contents of the approved folder, including the generated criteria and lock, and the contract's own entry in the canonical index at that commit. This applies to every merge method. G2 replacements name the current product predecessor. G3 and G4 pin the latest product receipt and replace their own deliverables, removing files dropped from the approved section. The latest receipt for the contract supplies the binding for preserved files and sections, including the G2 interaction design. A match records the folder and SHA-256 lock digest and sets the occurrence to `recorded`.

A landing waits while an earlier unrecorded merge of the same contract is pending, and stopping or resuming the predecessor run releases it. A failed match sets `merged-unverified`. Use the run ID and cause code from the worker log to locate the occurrence. Restore the latest receipted folder, its files and lock, and its index entry on main first. For a failed first publication, remove the unreceipted additions from main. Then open a new proposal PR and obtain a fresh approval for the affected gate. Follow the same order for `contract-drift`. The worker reports folders outside the current receipt bindings, and G5 uses only verified contract bytes.

The verification worker uses GitHub JSON endpoints on `api.github.com` and scopes installation tokens to a single numeric repository ID. Its GitHub writes are limited to commit statuses. The legacy Host contract merge action has been removed. The worker rejects redirect responses and reported final URLs that differ from the request. Run `node scripts/check-github-host-transport.mjs <installed-paperclip-server-directory>` against the target Paperclip host and SDK pair to check redirect handling and binary Git blob transport before deployment.
