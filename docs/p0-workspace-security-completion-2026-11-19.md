# Workspace lease and MCP deployment policy, 2026-11-19

This change supplies a global, database-backed lease table and an explicit admission boundary. A lease is keyed by the real path of the Git common directory, so aliases and linked worktrees contend across companies and runs within the same plugin database. Acquisition and takeover are atomic; fencing increases on every acquisition and stale owners cannot renew or release. The row is retained after release to preserve the counter. Identity resolution reads only bounded Git metadata (`.git` and `commondir`), never runs Git or repository hooks, and does not inspect `.git/config` or credentials. Missing metadata, temporary failures, and identity changes are distinct recovery outcomes.

A database lease cannot stop an expired process. Enabling the lease store and declared-write admission requires a host that actually fences writes, revokes expired writers and isolates Git credentials. The current Paperclip integration has no such attested capability, so pinned `node.workspace.writeAccess` or `pack.workspace.writeAccess` of `exclusive` is rejected with `host_capability_missing` before assignment. Work with no declaration remains **legacy unmanaged**; this is not a physical lock on those executions. Temporary agents already reject write delegation. The lease store is an integration primitive, not a claim that the external Paperclip host enforces it. A future host must bind the resolved identity, fence, expiry, renewals and terminal release to actual write authority; it must also prevent a holder from changing Git shared config or accessing credentials. Recheck the identity at the host boundary and on recovery. A symlink or directory replaced between resolution and use requires host-level handle-based protection. Windows path handling uses Node realpath and case normalization; junction aliases are tested where permitted, but volume aliases, filesystem case-sensitive directories, remote hosts and Windows process revocation have not been verified.

The secret-free inventory check takes an operator-attested JSON file, not actual MCP config or credentials: `node scripts/check-mcp-inventory.mjs <inventory.json>`. Its exact schema is `{ "schema": "polyforge.mcp-inventory.v1", "complete": true, "servers": [{ "id": "git-main", "kind": "git", "version": "2026.11.18" }] }`. Kinds are `git`, `filesystem`, `everything`, `fetch`, and `inspector`; minimum versions are respectively `2026.11.18`, `2.4.0`, `2.3.1`, `2026.11.11`, and `2.14.0`. Unknown fields, duplicate IDs, unknown server kinds and malformed or lower versions fail. `complete: true` is an operator assertion, not discovery: an empty list is valid only when the deployment actually has no MCP servers. A project-scoped text search of source/deployment files found no MCP server configuration or dependencies. This is not evidence of the machine's installed MCP versions or other deployments; obtain and verify the actual inventory separately. No unused MCP dependency was added. File paths, repository content, tool outputs, server-provided instructions and aliases remain untrusted and must not become authority for policy or workspace identity.

Validation: `node --test tests/plugin/workspace-security.test.mjs` covers resolved linked worktrees and aliases, recovery categories, simulated atomic lease contention/release/expiry/fencing, host capability failure, the declared-write admission gate, and inventory policy. The contention test uses an in-memory database model; PostgreSQL execution and physical process fencing require integration tests on the target host. No external MCP installation was inspected. The repository's dispatch integration test should also run after concurrent dispatch changes settle.

Lease keys are global only inside the plugin's database namespace. Separate databases or plugin namespaces sharing a physical repository do not coordinate through this table; they require one shared fencing authority. Admission resolves the host-attested identity again and checks the worktree and both Git metadata directories against host-supplied allowed roots. A future host receipt must bind the workspace key and unexpired fence to the exact company, run, node, attempt and phase. These checks do not close filesystem replacement races without host handle-based enforcement.

The standalone budget function `checkMcpConfigBudget` limits parsed JSON depth (12), total values (2000), object/array entries (100), key length (128), string length (4096), and pattern text (256); it rejects dangerous object keys. It never compiles or executes patterns and is not a JSON Schema validator or an MCP gateway. The inventory CLI runs this budget before its stricter exact inventory schema; no live MCP request path is connected to this utility.

The current dispatch path intentionally supplies no host adapter to the declared-write gate and cannot acquire a workspace lease. Before wiring an adapter, design an idempotent lease admission bound to an attempt, coordinate it with the dispatch slot reservation, compensate both sides on failure or race, and release only once the host has revoked or finished the writer. Replays must revalidate authority without acquiring another writer. This is necessary even when the durable lease itself is atomic.
